# Sentilex: Анализ тональности

Проект **Sentilex** предназначен для интеллектуального анализа текста и определения эмоциональной окраски (тональности) загруженных документов. В репозитории поддерживаются web-интерфейс и desktop GUI на PySide6: оба варианта позволяют загрузить `.txt`-файл, указать параметры анализа и получить результат в виде текстового файла с разметкой и графика распределения тональности по тексту. Desktop-вариант дополнительно умеет экспортировать автономный Python-скрипт для ручной доработки визуализации и повторного запуска анализа вне приложения.

Текущий формат результата:

- текстовый файл содержит построчные оценки предложений, блок агрегированных метрик графика
  и отдельный блок эмоциональных фаз;
- PNG-график показывает исходную кривую, одно сглаживание (`uniform_filter1d`),
  усиленные адаптивные фоны эмоциональных фаз, встроенный нижний блок метрик
  и краткую сводку фаз;
- desktop дополнительно сохраняет `.py`-скрипт с текущей фазовой логикой анализа
  и блоком параметров графика для ручного редактирования;
- разделы текста отображаются на графике как визуальные маркеры и не участвуют в разрезании чанков анализа.

## Эмоциональные фазы тональности

Эмоциональная фаза — непрерывный участок сглаженной кривой тональности,
которому присвоен один тип. Это прежняя сегментация тональности, отдельная от
[эмоциональных кластеров NRC](#desktop-nrc-emolex). Это сегментация кривой, а не тематическая кластеризация
предложений или отдельная обучаемая модель.

Фазы рассчитываются автоматически в web и desktop при обычном анализе `.txt`:

1. Предложения объединяются в фрагменты заданного размера; всем предложениям
   фрагмента присваивается его средняя оценка RuSentiLex.
2. Кривая сглаживается скользящим средним с окном `2 * chunk_size + 1`.
3. Для сглаженной кривой рассчитываются среднее `μ` и стандартное отклонение `σ`.
   Значения выше `μ + 0.5σ` получают положительный тип, ниже `μ - 0.5σ` —
   отрицательный, остальные, включая границы, — нейтральный.
4. Соседние точки одного типа объединяются. Участки короче
   `max(2, chunk_size // 2)` предложений присоединяются к соседним фазам;
   подробные правила приведены в [техническом описании](PROJECT_OVERVIEW.md#эмоциональные-кластеры-фазы).

Тип фазы относителен среднему конкретного текста. Например, при `μ = 0.20`
и `σ = 0.10` нейтральная зона равна `[0.15; 0.25]`: значение `0.10` относится
к отрицательному типу, хотя само оно выше нуля. После объединения коротких
участков внутри фазы могут оставаться точки других исходных типов.

На PNG фазы показаны зелёным, серо-голубым и красным фоном. Внизу выводятся
число фаз, доли `+ / 0 / -` и средняя длина. TXT содержит блоки
`Эмоциональные фазы` и `Интервалы фаз`: количество фаз каждого типа, среднюю
длину, максимальную длину положительной и отрицательной фаз, доли и интервалы.
Например, запись `50-84` охватывает 35 предложений; номера начинаются с 1,
обе границы включены, среднее интервала рассчитано по сглаженной кривой.

Доля типа — число предложений в итоговых фазах этого типа, делённое на общее
число предложений. Это не доля фаз по количеству и не распределение оценок
по фиксированным порогам `> 0.1` / `< -0.1` на web-странице. Проценты на PNG
округлены до целых, в TXT — до двух знаков, поэтому сумма отображаемых долей
может отличаться от 100% из-за округления.

Размер фрагмента влияет на исходные оценки фрагментов, окно сглаживания и
минимальную длину фазы. При сравнении запусков фиксируйте этот параметр;
границы и типы фаз могут меняться при его изменении. Для web допустимы
10–500 предложений (по умолчанию 50), в desktop после выбора файла размер равен 1,
допустимый диапазон — 1…число предложений выбранного текста. Отдельно включать фазы не нужно;
экспортированный desktop PY воспроизводит их при тех же входных данных и размере
фрагмента. Фазовая сегментация сама по себе не изменяет оценки RuSentiLex.

## Основные файлы
* `Dockerfile`
Описывает среду для сборки Docker-образа (установка `Python`, необходимых библиотек и копирование исходников).

* `requirements.txt`
Список `Python`-зависимостей (`Flask`, `numpy`, `pandas`, `nltk` и др.).

* `app.py`
Главный файл web-приложения `Flask`. Здесь определяются маршруты:

  * `/` для загрузки файла,

  * `/results/<filename>` для отображения результатов,

  * `/download/<filename>` для скачивания файлов,

  * а также вспомогательные функции.

* `scripts/functions.py`
Логика обработки текста, вычисления тональности, построения графика и сохранения результатов.

* `desktop/main.py`, `desktop/ui/main.ui`, `desktop/style.qss`
Desktop-приложение на `PySide6`: окно выбора файла, параметры анализа, preview результатов и визуальное оформление интерфейса.

* `templates/upload.html` и `templates/results.html`
HTML-шаблоны, используемые Flask для рендеринга страниц загрузки и результатов соответственно.

* `uploads/`
Папка, куда складываются загруженные пользователем файлы.

* `results/`
Папка, где сохраняются результаты анализа (текстовые файлы и графики).

## Desktop GUI MVP (локальный запуск)

Desktop-часть использует те же функции анализа, что и веб, но держит Qt-зависимости отдельно.

Desktop UX (MVP):
- главное окно стартует в безопасном размере под доступную рабочую область экрана;
- на широких экранах используется широкий рабочий layout: параметры слева, результаты справа;
- на более узких окнах layout переключается в stacked-режим, а при нехватке высоты контент прокручивается без наложения виджетов;
- вводный текст desktop-окна нейтрально описывает назначение программы, без упора на layout;
- размер фрагмента в desktop задаётся в предложениях, а максимальное значение вычисляется по выбранному `.txt` файлу;
- ползунок размера фрагмента использует округлённые шаги и при необходимости добавляет точный максимум по числу предложений файла;
- после анализа текстовый результат показывается в preview-блоке;
- preview графика кликабелен и открывается в большом модальном окне;
- после анализа desktop позволяет сохранить `TXT`, `PNG` и автономный `PY`-скрипт для Google Colab или локального повторного запуска;
- повторный анализ подряд поддерживается (результаты и preview обновляются);
- PNG-график содержит читаемые адаптивные фоны эмоциональных фаз, нижний блок метрик,
  краткую сводку фаз и не обрезает подписи оси X.

```bash
# web/runtime зависимости
.venv/bin/pip install -r requirements.txt

# desktop-only зависимости (не для Docker/web)
.venv/bin/pip install -r desktop/requirements.txt

# запуск desktop приложения
.venv/bin/python tools/prepare_nrc2022.py
.venv/bin/python desktop/main.py

# non-GUI smoke: двойной прогон анализа и проверка обновления TXT/PNG/PY
.venv/bin/python desktop/smoke_reanalysis.py

# non-GUI smoke: экспортированный PY воспроизводит TXT результата
.venv/bin/python desktop/smoke_export_script.py

# headless smoke: проверка wide/stacked layout без display
QT_QPA_PLATFORM=offscreen .venv/bin/python desktop/smoke_layout.py

# headless smoke: проверка значений ползунка размера фрагмента
QT_QPA_PLATFORM=offscreen .venv/bin/python desktop/smoke_chunk_slider.py
```

Smoke-проверки повторного анализа и экспорта запускайте последовательно:
они записывают результаты по одинаковым путям.

Рендер parity-экрана:
```bash
# если есть display
.venv/bin/python desktop/render_main.py

# для WSL/headless
QT_QPA_PLATFORM=offscreen .venv/bin/python desktop/render_main.py
```

## Windows build (.exe)

Сборку `PyInstaller` нужно выполнять **на Windows** (кросс-компиляция из Linux/WSL не поддерживается).
Для desktop сборки используйте Python `3.10` или `3.11` (из-за совместимости `pymorphy2`).

```powershell
powershell -ExecutionPolicy Bypass -File tools/build_windows.ps1
```

Опционально `onefile`:

```powershell
powershell -ExecutionPolicy Bypass -File tools/build_windows.ps1 -OneFile
```

Примечание: `tools/build_windows.ps1` намеренно пинует `setuptools<81`, потому что `pkg_resources` удалён в новых версиях, а для текущего стека сборки/рантайма это нужно.

Где искать результаты сборки:
- `dist/SentiSoft-NRC2022-Literary-v2/` для `onedir` (по умолчанию)
- `dist/SentiSoft-NRC2022-Literary-v2.exe` для `onefile`

Важно: desktop приложение в режиме `.exe` пишет `results/` рядом с исполняемым файлом, поэтому каталог запуска должен быть доступен на запись.

В bundle включаются обязательные desktop-ресурсы:
- `desktop/ui/main.ui`
- `desktop/style.qss`
- `scripts/RuSentilex-2017.txt`

## Установка и запуск

1. ### Локальный запуск (без `Docker`)
   * Убедитесь, что у вас установлен `Python 3.10`+ (либо другая совместимая версия).
   * Установите зависимости:
     ```bash
     pip install -r requirements.txt
     ```
   * Запустите приложение в веб-режиме:
     ```bash
     python app.py
     ``` 
   * Перейдите в браузере по адресу http://127.0.0.1:5000
   * Запустите приложение в десктоп-режиме:
     ```bash
     python desktop.py
     ```
     Откроется окно `pywebview` с интерфейсом Sentilex. При закрытии окна Flask-сервер останавливается автоматически.

2. ### Сборка и запуск в `Docker`
   * Сборка Docker-образа:
      ```bash
      docker build -t sentilex_v10 .
      ```
      Эта команда выполнит инструкции в `Dockerfile`, соберёт образ с именем `sentilex_v10` и установит все необходимые зависимости.
   * Запуск контейнера:
      ```bash
      docker run -p 5000:5000 sentilex_v10
      ```
      Здесь:
      `-p 5000:5000` перенаправляет порт 5000 контейнера на порт 5000 хоста, чтобы к приложению можно было обратиться по адресу http://localhost:5000.
   * Использование:
      * Откройте http://localhost:5000 в браузере.
      * Загрузите .txt-файл и укажите параметры анализа (например, «Размер фрагмента»).
      * После анализа вы будете перенаправлены на страницу результатов, где сможете:
        * Скачать текстовый файл с результатами, метриками графика и сводкой эмоциональных фаз.
        * Скачать или просмотреть график распределения тональности с фоновым выделением эмоциональных фаз.


## Примечания
* Файл `RuSentilex-2017.txt` (в папке `scripts/`) содержит словарь тонально окрашенных слов и используется для вычисления эмоциональной окраски предложений.
* Папки `uploads/` и `results/` создаются автоматически при запуске приложения, если их нет.
* При желании вы можете дополнительно кастомизировать стили в файлах `templates/upload.html` и `templates/results.html`, чтобы добиться нужного внешнего вида.

## Проверка перед интеграцией

`make verify` запускает проверку округления TXT и golden web-сценарий в Docker
с Python 3.10. При наличии `.venv/bin/python` проверка округления выполняется и
локально; отдельно: `.venv/bin/python tools/smoke_chunk_precision.py`.
Оценки фрагментов складываются последовательно, чтобы сохранить историческое
округление TXT и на Python 3.12+.

Docker-контекст ограничен web-исходниками через `.dockerignore`; локальные
результаты, тексты, статья и виртуальные окружения в образ не копируются.
Системные компиляторы и Git для текущих runtime-зависимостей не требуются.

Если опубликованный Docker-порт недоступен с хоста, используйте
`GOLDEN_HTTP_MODE=container make verify`: тест выполняет HTTP-загрузку текста
и скачивание TXT внутри контейнера и сравнивает результат с тем же baseline.
Этот режим не проверяет доступность опубликованного порта с хоста.
При недоступном Buildx можно временно добавить `DOCKER_BUILDKIT=0`.
Проверенная команда для такого окружения:

```bash
GOLDEN_HTTP_MODE=container DOCKER_BUILDKIT=0 make verify
```

Русский ресурс встроен в локальный exe; выбирать словарь или подключаться к сети при запуске не требуется. Источник — [NRC EmoLex 0.92](https://saifmohammad.com/WebPages/NRC-Emotion-Lexicon.htm), Saif M. Mohammad, Peter D. Turney, NRC Canada.

**Русский перевод 2022 тоже машинный: Google Translate, август 2022.** Вручную через краудсорсинг размечалась английская основа. Авторы отмечают улучшение перевода относительно 2017 года, но ошибки и транслитерации сохраняются. В конкретной русской таблице 14154 строки; после отбора эмоциональных записей и объединения нормализованных переводов — 3707 ключей в исходном режиме и 3702 после правок v1 и 3693 в v2. Это не 14 тысяч независимых русских эмоциональных лемм. URL и контрольные суммы закреплены в [сведениях об источнике](scripts/data/NRC2022.SOURCE.md).

Русский TXT и оригинальный README лежат в игнорируемом `scripts/data/nrc2022/`. Они входят только в локальный исследовательский exe, не публикуются с исходниками и не включаются в web Docker image. Windows-сборщик подготовит ресурс, если его ещё нет. При обычной работе exe сеть не используется; `openpyxl` и сохранённый путь NRC не нужны. Пользовательский сценарий — собственное некоммерческое исследование и демонстрация программы на конференции без передачи словаря/exe.

После **каждого выбора файла размер фрагмента равен 1**. Числовое поле принимает 1…число предложений, ползунок предлагает 1…10, затем десятки и точный максимум; введённые вручную значения добавляются в набор. До выбора управление отключено, минимум 1, максимум неизвестен. Размер общий для тональности и эмоций. Шаг подписей глав меняет только подписи по порядку (1, 1+N, …) и сохраняется в тональном PY как `CHAPTER_LABEL_STEP`.

Вкладка «Эмоциональные кластеры» сохраняет градиенты под сглаженной кривой RuSentiLex и матрицу «Преобладающие эмоции по фрагментам», теперь с восемью строками. Цвета: злость — красный, грусть — синий, радость — жёлтый, страх — фиолетовый, удивление — бирюзовый, ожидание — оранжевый, отвращение — розовый, доверие — зелёный. При равных максимумах показаны все категории; штриховка означает отсутствие совпадений. Чёрная линия — прежнее скользящее среднее тональности с окном `2 × размер фрагмента + 1`; высота заливки не измеряет силу эмоций.

«Плотность эмоций» показывает восемь ступенчатых кривых: **маркеры категории / все слова фрагмента × 100**. Это маркеры на 100 слов, а не доля среди эмоциональных слов. Значение постоянно внутри фрагмента; ось X — номера предложений, границы сохранены. Общий знаменатель позволяет сравнивать разную длину, но не меняет преобладающую категорию внутри фрагмента. Выбор выполняется до округления; при нуле слов плотности нулевые.

В обоих CSV добавлены последние две колонки «Профиль словаря» и «SHA256 профиля»; имя и контрольная сумма также записаны в TXT/HTML и кратко в PNG. Смена профиля очищает результаты и требует нового анализа. Во время анализа переключатель отключён.

«Маркеры кластеров» показывает связи вида «Найдено: “боюсь” → страх», текст после предобработки и подробности с леммами/счётчиками/плотностями. Повторы учитываются отдельно. Нормализованные переводы объединяют категории без дублей. Самое длинное словосочетание считается одним маркером без перекрытий; все его слова входят в знаменатель. Одно вхождение может пополнять несколько категорий. Метки NRC positive/negative не заменяют расчёт тональности RuSentiLex.

| Окончание имени | Содержимое |
|---|---|
| `_emotions.png` | Тональность, градиенты и восьмистрочная матрица |
| `_emotion_density.png` | Восемь кривых, маркеров на 100 слов |
| `_emotions.csv` | Фрагмент, диапазон, число слов, восемь счётчиков/плотностей и преобладающие эмоции |
| `_emotion_sentences.csv` | Номера фрагмента/предложения, текст, слова, восемь счётчиков/плотностей, категории и найденные маркеры; включая предложения без совпадений |
| `_emotions.txt` | Сводка, источник/перевод, фрагменты, предложения и основания меток |
| `_emotions.html` | Автономный экранированный отчёт, открывается без сети |

CSV использует UTF-8 BOM и `;`, плотности — отношения с точкой (`0.25`); GUI/TXT/HTML/PNG показывают маркеры на 100 слов (`25.00`). Доли маркеров по сумме восьми счётчиков и доли текста по предложениям с равным разделением между преобладающими категориями остаются отдельными показателями. При выборе другого файла, повторе и ошибке старые просмотры/действия очищаются; частичные файлы эмоций удаляются.

В исходном переводе `wot → что` имеет метку «доверие». Исправленный профиль исключает эту запись, а также омографическое «ага» и отдельные служебные соответствия; `spite` уточнено как «злоба», `nothingness` — как «небытие». Слова остаются в тексте и знаменателе плотности, многословные выражения не разбираются фильтром на части. Содержательные «правда», «конечно», «любовь», междометия и другие неоднозначные случаи сохранены. Эти правки не доказывают измеренного улучшения литературной интерпретации. Контекст, отрицания и ирония по-прежнему не интерпретируются. Коллизия нормализации «гора/горе» остаётся известным ограничением; результаты нужно проверять по найденным маркерам.

Текущий локальный exe: `dist/SentiSoft-NRC2022-Literary-v2.exe` ([запись выпуска и SHA256](docs/releases/NRC2022-Literary-v2-2026-11-08.md)). Дата сборки и NRC2022 видны в окне. Сборка на NTFS сохраняет старые exe и не закрывает открытые программы. Для WSL/UNC виртуальное окружение — `%LOCALAPPDATA%\SentilexBuild\venv`; `-VenvPath` принимает абсолютный путь Windows. Проверка:

```powershell
powershell -ExecutionPolicy Bypass -File tools/smoke_frozen.ps1
# Проверить прежний v1 и исходный режим в той же сборке:
powershell -ExecutionPolicy Bypass -File tools/smoke_frozen.ps1 -Profile literary_v1 -ReportName v2-v1
powershell -ExecutionPolicy Bypass -File tools/smoke_frozen.ps1 -Profile raw -ReportName literary-raw
# Для другого расположения:
powershell -ExecutionPolicy Bypass -File tools/smoke_frozen.ps1 -ExePath "C:\путь\SentiSoft-NRC2022-Literary-v2.exe"
```

Smoke запрещает исходящие Python socket-соединения, проверяет реальные worker/UI, встроенный русский TXT/README и источник, все шесть файлов, а также прежний тональный golden после CRLF-нормализации. JSON и три снимка сохраняются в dist. Аудит источника без загрузки произведений: `.venv/bin/python tools/audit_nrc_profile.py`. Проверки `.venv/bin/python desktop/smoke_emotion_profile.py` и `.venv/bin/python desktop/smoke_emotion_profile_v2.py` проверяют правки и независимые примеры прозы/грамматики. Тональность RuSentiLex, эмоциональные фазы и standalone PY не изменены. [Описание для статьи](docs/article_emotional_clusters.md). Предыдущая RusEmoLex-сборка и [её запись выпуска](docs/releases/RusEmoLex-2026-11-08.md) сохранены для сравнения.
