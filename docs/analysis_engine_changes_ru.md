# Изменения движка анализа

Этот файл простым языком фиксирует намеренные изменения поведения анализа Sentilex.
Обновляйте его каждый раз, когда изменения в `scripts/functions.py`,
`scripts/export_script.py` или в orchestration-логике анализа меняют то,
как входной текст обрабатывается, измеряется, отображается на графике,
экспортируется или записывается в результирующие файлы.

Цель файла - сделать изменения движка понятными без чтения Python-кода.

Как стало: оригинальный Russian-NRC-EmoLex.txt из закреплённого ZIP автора (2022), SHA256 96849cb99a395e1e749030fa6c115860e2664f7690a1beac82c47485d42ce75a. В русской таблице 14154 строки, после отбора эмоциональных переводов и объединения нормализованных записей — 3707 ключей. Вектор: злость/грусть/радость/страх/удивление/ожидание/отвращение/доверие. Первые пять цветов/индексов сохранены, добавлены три; CSV/кривые/матрица используют восемь категорий. Бинарная метка даёт один вклад на вхождение; positive/negative не заменяет RuSentiLex. Подготовка закреплённого ресурса вынесена в отдельную команду; при runtime сеть и openpyxl не нужны. Прежние сборки/ресурсы сохранены.

Зачем: пользователь запросил попробовать NRC 2022 в собственной исследовательской программе для конференции, без распространения. Категории/счётчики/колонки эмоций меняются намеренно; longest-match/no-overlap, объединение переводов, повторы, плотности/единицы/равенства, default 1 и шесть основ имён сохранены. ## 2026-11-07 - Историческое округление TXT на разных версиях Python

Файлы и функции:
- `scripts/functions.py::calculate_sentences_sentiments`;
- та же функция в шаблоне `scripts/export_script.py`;
- `tools/smoke_chunk_precision.py`, `tools/verify.sh`, `tools/golden_e2e.sh`,
  `tools/golden_http.py`, `Dockerfile`, `.dockerignore`.

Как было: среднее фрагмента рассчитывалось через встроенную `sum()`.
Изменение алгоритма сложения float в Python 3.12 меняло округление 100 строк
TXT в golden-сценарии; это воспроизводилось и на прежнем движке из HEAD.
В контейнере с Python 3.10 результат совпадал с baseline.

Как стало: в runtime и автономном экспорте явно сохранено последовательное
сложение слева направо. Это восстанавливает исторический TXT без замены baseline.
Регрессионный тест проверяет пример, где прежний формат требует `+0.22`,
а встроенная `sum()` на Python 3.12 приводила к `+0.21`.

Зачем: обеспечить воспроизводимость результата между версиями Python.
Лексические оценки, границы фрагментов, алгоритм фаз и структура TXT не изменены.
К сборке добавлен `.dockerignore`; удалена установка ненужных системных
компиляторов и Git, падавшая из-за ответов Debian 404.

Проверка (2026-11-07):
- тест округления падал до исправления на Python 3.12 и проходит после;
- `GOLDEN_HTTP_MODE=container DOCKER_BUILDKIT=0 make verify`: пройдено,
  включая тест округления в контейнере Python 3.10 и на хосте Python 3.12,
  HTTP-загрузку текста, скачивание TXT и побайтное сравнение с golden;
- `.venv/bin/python desktop/smoke_export_script.py`: пройдено;
- `.venv/bin/python desktop/smoke_reanalysis.py`: пройдено, отдельно после экспорта;
- локальный полный TXT на Python 3.12 побайтно совпадает с golden.

HTTP-доступ с хоста к опубликованному порту в этом окружении не работал.
Явный режим `GOLDEN_HTTP_MODE=container` проверяет тот же HTTP-сценарий внутри
контейнера, но не подтверждает доступность порта с хоста.

Описание самого фазового алгоритма и трактовка долей находятся в
[техническом описании](../PROJECT_OVERVIEW.md#эмоциональные-кластеры-фазы),
пользовательская инструкция — в [README](../README.md#эмоциональные-кластеры-фазы).
