# Sentilex: техническое описание проекта

Этот файл предназначен как подробная справка о проекте Sentilex. Его удобно
передавать вместе с `README.md` и `AGENTS.md`, когда нужно быстро ввести внешнего
собеседника в устройство проекта.

`README.md` описывает назначение, запуск, пользовательские сценарии и сборку.
`AGENTS.md` полезен как источник рабочих правил: в нем зафиксированы структура
репозитория, команды проверки, поведение golden regression и ограничение на
изменение поведения без явного запроса. Этот файл дополняет их техническим
описанием web-части, desktop-части и общего движка анализа.

## Назначение проекта

Sentilex анализирует эмоциональную тональность русскоязычного текста. Пользователь
загружает `.txt`-файл, задает размер фрагмента анализа в предложениях и получает:

- текстовый результат с оценкой тональности для каждой строки-предложения;
- PNG-график распределения тональности по тексту;
- блок агрегированных метрик графика;
- в desktop-версии дополнительно автономный Python-скрипт для повторного запуска
  анализа и ручной доработки визуализации.

В проекте есть две пользовательские оболочки над общей логикой:

- web-приложение на Flask;
- desktop-приложение на PySide6, собираемое в Windows-приложение через PyInstaller.

Основная логика анализа находится не в интерфейсах, а в `scripts/functions.py`.
Web и desktop используют один и тот же пайплайн обработки, поэтому изменение
движковой части влияет на оба варианта приложения.

## Основные модули

- `app.py` - Flask-приложение, маршруты загрузки/результатов/скачивания и функция
  `process_text`, которая оркестрирует анализ.
- `scripts/functions.py` - движок анализа: загрузка RuSentiLex, предобработка,
  выделение предложений и секций, расчет тональности, построение графика,
  сохранение TXT-результата.
- `scripts/export_script.py` - генератор автономного Python-скрипта анализа для
  desktop-версии.
- `scripts/RuSentilex-2017.txt` - лексикон RuSentiLex, из которого строятся
  словари слов и словосочетаний с числовой оценкой тональности.
- `templates/upload.html` и `templates/results.html` - HTML-шаблоны web-интерфейса.
- `desktop/main.py` - контроллер desktop-приложения, запуск анализа в отдельном
  потоке, предпросмотр и сохранение результатов.
- `desktop/ui/main.ui` - Qt Designer layout основного desktop-окна.
- `desktop/style.qss` - QSS-стили desktop-интерфейса.
- `desktop/sentilex.spec` - PyInstaller spec для Windows-сборки.

## Web-часть

Web-приложение запускается из `app.py` и использует Flask. При старте создаются
каталоги `uploads/` и `results/`, после чего загружается RuSentiLex из
`scripts/RuSentilex-2017.txt`. Загруженные словари хранятся в глобальных
переменных `lexicon` и `phrase_lexicon`.

Поддерживаются основные маршруты:

- `GET /` - показывает форму загрузки файла;
- `POST /` - принимает `.txt`-файл и параметр `chunk_size`, сохраняет файл в
  `uploads/`, запускает обработку и перенаправляет на страницу результатов;
- `GET /results/<filename>` - показывает ссылки на результаты и preview графика;
- `GET /download/<path:filename>` - отдает файлы из `results/` для скачивания.

Функция `allowed_file` разрешает только расширение `.txt`. Имя файла проходит
через `secure_filename`, чтобы результат и загруженный файл имели безопасное имя.

Центральная функция web-пайплайна - `process_text(file_path, filename, chunk_size,
export_script_file=False)`. Она:

1. читает исходный UTF-8 текст;
2. выполняет предобработку через `functions.preprocess_text`;
3. выделяет предложения и секции через `functions.extract_sentences_and_sections`;
4. записывает служебный файл секций через `functions.write_sections_file`;
5. рассчитывает тональность предложений через
   `functions.calculate_sentences_sentiments`;
6. строит PNG-график через `functions.plot_sentiment_curve`;
7. сохраняет TXT-результат через `functions.save_results_to_text`;
8. при `export_script_file=True` дополнительно генерирует автономный `.py`-скрипт.

В web-версии пользователь получает TXT и PNG. Экспорт `.py` используется desktop-
оболочкой.

## Движок анализа

Движковая часть находится в `scripts/functions.py`. Она работает на уровне
правил, лексикона и морфологической нормализации.

### Загрузка RuSentiLex

`load_rusentilex(file_path)` читает `RuSentilex-2017.txt`, пропускает пустые
строки, комментарии и служебные строки. Для каждой записи берется лемма и
текстовая тональность. Тональность преобразуется в число:

- `positive` -> `1.0`;
- `negative` -> `-1.0`;
- `neutral` -> `0.0`;
- `positive/negative` -> `0.5`;
- неизвестные значения -> `0.0`.

Если лемма содержит пробел, запись попадает в `phrase_lexicon`; иначе - в
обычный `lexicon`.

### Предобработка текста

`preprocess_text(text)` нормализует входной текст построчно:

- сохраняет строки вида `{Раздел}` как маркеры секций;
- схлопывает повторяющиеся пробелы;
- удаляет неподдерживаемые символы;
- сохраняет русские и латинские буквы, цифры, базовую пунктуацию, дефисы, тире,
  кавычки и фигурные скобки.

Секции используются как визуальные маркеры на графике. Они не являются
предложениями и не оцениваются как текст.

### Предложения и секции

`extract_sentences_and_sections(text)` проходит по строкам обработанного текста.
Строки в фигурных скобках записываются как секции в формате `(название,
номер_следующего_предложения)`. Остальные строки разбиваются на предложения по
символам `.`, `!`, `?` с сохранением знака препинания в предложении.

Результат функции:

- `sentences` - список предложений для анализа;
- `sections` - список секций и позиций, где они начинаются.

### Лемматизация и фразы

Для морфологической нормализации используется `natasha.MorphVocab`. Слова и
фразы приводятся к нормальной форме. Дополнительно `ё` заменяется на `е`, чтобы
снизить расхождения между входным текстом и словарем.

`find_lemmatized_phrases(sentence, phrase_lexicon)` ищет словосочетания длиной
от 2 до 5 слов. Для каждого кандидата строится нормализованная лемматизированная
форма и проверяется наличие в фразовом словаре.

### Расчет тональности предложения

`calculate_sentiment(sentence, lexicon, phrase_lexicon)` считает среднее значение
тональности по найденным словарным совпадениям:

1. предложение делится на фрагменты по пунктуационным разделителям;
2. сначала ищутся лемматизированные фразы из `phrase_lexicon`;
3. найденные фразы добавляют свой score и затем удаляются из фрагмента;
4. оставшиеся слова лемматизируются и ищутся в `lexicon`;
5. слова отрицания `не`, `ни`, `никак`, `нисколько` инвертируют следующую
   ненулевую тональность;
6. если совпадений нет, результат предложения равен `0`.

Финальная оценка предложения - среднее по найденным словам и фразам.

### Чанки

`calculate_sentences_sentiments(sentences, section_positions, chunk_size, lexicon,
phrase_lexicon)` группирует предложения в фрагменты длиной `chunk_size`. Для
каждого фрагмента рассчитываются оценки отдельных предложений, затем берется
среднее значение фрагмента. Это среднее записывается для всех предложений
фрагмента, поэтому выходной список имеет ту же длину, что и `sentences`.

В текущем web/desktop пайплайне в расчет передается пустой список `section_positions`.
Позиции секций используются при построении графика как вертикальные маркеры, но
не разрезают чанки анализа.

### График и метрики

`plot_sentiment_curve(...)` строит PNG-график с двумя кривыми:

- исходные значения тональности;
- сглаженная кривая через `scipy.ndimage.uniform_filter1d`.

Размер окна сглаживания равен `2 * chunk_size + 1`.

На графике отмечаются максимумы и минимумы исходной и сглаженной кривой,
проводятся горизонтальные линии экстремумов, средняя линия и область
`mean +/- volatility`. Если в тексте есть секции, они отображаются вертикальными
линиями и подписями на оси X.

Метрики графика:

- `Волатильность` (`volatility_amplitude`) - стандартное отклонение сглаженной
  кривой;
- `Общая изменчивость` (`path_length`) - сумма модулей разностей соседних точек
  сглаженной кривой;
- `Удельная изменчивость` (`mean_change`) - `path_length / len(smoothed_curve)`.

Эти метрики выводятся в нижнем блоке PNG и добавляются в конец TXT-результата.

### TXT-результат

`save_results_to_text(...)` сохраняет строки вида:

```text
+0.25 Текст предложения.
-0.50 Текст другого предложения.
```

После списка предложений, если переданы метрики, добавляется блок:

```text
Метрики графика:
Волатильность: ...
Общая изменчивость: ...
Удельная изменчивость: ...
```

## Desktop-часть

Desktop-приложение находится в `desktop/main.py` и построено на PySide6. Оно
использует тот же backend, что и web-версия: импортирует `app.py` как `web_app`
и вызывает `web_app.process_text(...)`.

### Runtime-окружение

При запуске desktop-приложение определяет:

- `PROJECT_ROOT` - корень репозитория в режиме разработки;
- `RESOURCE_ROOT` - путь к bundled-ресурсам при запуске из PyInstaller;
- `RUNTIME_ROOT` - каталог рядом с исполняемым файлом в frozen-режиме или корень
  проекта при обычном запуске.

`prepare_runtime_environment()` создает `results/` и `uploads/`. В frozen-режиме
она также копирует bundled `scripts/RuSentilex-2017.txt` в runtime-каталог, чтобы
импортированный `app.py` мог загрузить лексикон по ожидаемому пути.

Для frozen-сборки также настраивается `PYMORPHY2_DICT_PATH`, чтобы морфологические
словари были доступны из bundle.

### UI и контроллер

Окно загружается из `desktop/ui/main.ui` через `QUiLoader`, стили применяются из
`desktop/style.qss`. Контроллер `MainWindowController` связывает виджеты,
обрабатывает выбор файла, запуск анализа, предпросмотр и сохранение результатов.

Desktop UI поддерживает два режима layout:

- wide-режим при достаточной ширине: панель параметров слева, результаты справа;
- stacked-режим при меньшей ширине: блоки идут вертикально и прокручиваются.

Начальный размер окна подбирается под доступную область экрана.

### Выбор файла и размер фрагмента

Пользователь выбирает `.txt` через `QFileDialog`. Файл проверяется через ту же
`web_app.allowed_file`, что и web-версия. После выбора файл читается как UTF-8,
предобрабатывается и разбивается на предложения, чтобы определить количество
доступных предложений.

Слайдер размера фрагмента строится не как произвольный диапазон, а как список
допустимых значений:

- если предложений 10 или меньше, доступны все значения от `1` до числа
  предложений;
- если предложений больше 10, доступны шаги по 10 и точный максимум, если он не
  кратен 10.

Значение по умолчанию - `50`, если оно доступно; иначе ближайшее меньшее значение,
или максимальное доступное.

### Запуск анализа

Анализ выполняется в отдельном `QThread`, чтобы интерфейс не блокировался.
`AnalysisWorker` вызывает:

```python
web_app.process_text(
    str(self.file_path),
    filename,
    self.chunk_size,
    export_script_file=True,
)
```

После успешного анализа worker возвращает пути к TXT, PNG и PY. Контроллер
загружает TXT в preview-блок, загружает PNG в `QPixmap`, показывает preview
графика и включает кнопки сохранения.

При ошибке интерфейс переводится в состояние `error`, preview очищается, а
пользователю показывается `QMessageBox`.

### Результаты desktop-анализа

Desktop-версия после анализа позволяет:

- просмотреть TXT-результат внутри приложения;
- увидеть preview PNG-графика;
- открыть график в большом модальном окне;
- сохранить копию TXT;
- сохранить копию PNG;
- сохранить автономный PY-скрипт;
- открыть папку `results/`.

Повторный анализ поддерживается: текущие пути и preview сбрасываются перед новым
запуском, затем заменяются новыми результатами.

## Автономный экспортируемый Python-скрипт

`scripts/export_script.py` генерирует самостоятельный `.py`-файл. Он содержит:

- копию логики анализа;
- встроенный RuSentiLex как compressed base64 payload;
- CLI-интерфейс с `input_path`, `--chunk-size`, `--output-dir`;
- блок параметров визуализации, который можно вручную редактировать;
- построение TXT и PNG без запуска Flask или PySide6-приложения.

Экспорт нужен desktop-пользователю, чтобы повторить анализ вне приложения,
например локально или в notebook-среде, и при необходимости изменить оформление
графика.

## Windows-сборка

Windows-сборка описана в `desktop/sentilex.spec` и запускается через
`tools/build_windows.ps1`. PyInstaller получает entrypoint `desktop/main.py`.

В bundle включаются:

- `desktop/ui/main.ui`;
- `desktop/style.qss`;
- `scripts/RuSentilex-2017.txt`;
- словари `pymorphy2-dicts-ru`;
- metadata для `pymorphy2-dicts-ru`.

Spec поддерживает два режима:

- `onedir` - каталог `dist/SentiSoft/`;
- `onefile` - файл `dist/SentiSoft.exe`, включается через переменную окружения
  `SENTILEX_ONEFILE=1` в build-скрипте.

Desktop-приложение в frozen-режиме пишет runtime-результаты рядом с исполняемым
файлом, поэтому каталог запуска должен быть доступен на запись.

## Входные данные и выходные артефакты

Вход:

- `.txt`-файл в кодировке UTF-8;
- размер фрагмента анализа в предложениях;
- опциональные секции в тексте в формате `{Название секции}`.

Выход:

- `<filename>_results.txt` - оценки предложений и метрики;
- `<filename>_sentiment_curve.png` - график тональности;
- `<filename>_analysis_code.py` - только в desktop-сценарии, автономный скрипт;
- `sections.txt` - служебный файл с секциями.

Каталоги:

- `uploads/` - загруженные web-файлы;
- `results/` - результаты анализа;
- в frozen desktop-сборке эти каталоги создаются относительно каталога
  исполняемого файла.

## Проверки и регрессионный контракт

В проекте действует гарантия "behavior freeze": поведение анализа нельзя менять
без явного запроса. После изменений кода нужно запускать:

```bash
make verify
```

Fallback-команда:

```bash
./tools/verify.sh
```

Проверка включает компиляцию Python-файлов и golden e2e regression:

1. запускается приложение в Docker;
2. загружается `texts/chast__7.txt`;
3. скачивается TXT-результат;
4. результат сравнивается с golden baseline `results/chast_7_result.txt`.

Если изменение golden-результата ожидаемое, baseline должен обновляться в том же
изменении с объяснением причины.

Для desktop-части есть дополнительные smoke-проверки, которые используются при
изменении соответствующих областей:

- `desktop/smoke_reanalysis.py` - повторный анализ и обновление результатов;
- `desktop/smoke_export_script.py` - экспортированный Python-скрипт воспроизводит
  TXT-результат;
- `desktop/smoke_layout.py` - wide/stacked layout без display;
- `desktop/smoke_chunk_slider.py` - значения слайдера размера фрагмента.

## Важные ограничения

- Поддерживаемый пользовательский вход - `.txt`.
- Основной сценарий предполагает UTF-8 текст.
- RuSentiLex является словарной основой анализа; модель не обучается в runtime.
- Секции `{...}` используются для разметки графика и не являются анализируемыми
  предложениями.
- Web и desktop должны оставаться совместимыми по результатам, так как используют
  общий backend.
- Не стоит рефакторить движок, web и desktop одновременно без отдельной причины:
  изменение `scripts/functions.py` имеет широкий эффект.
- Изменения setup, портов, env vars, команд запуска, verification flow,
  dependencies или пользовательского UI должны отражаться в `README.md` и при
  необходимости в `AGENTS.md`.
